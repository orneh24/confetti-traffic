About this test

Pervium tests end-to-end connectivity between nodes placed on the network segments under test. Each node runs a small set of real servers and, once a minute, connects to every other node as a client. Results go to a central hub that draws them as a matrix.

The HTTP test

The H column of the matrix is this site. The testing node requests, in order: index.html, style.css, app.js, about.html and report.html. Each response must be HTTP 200 and must match the SHA-256 of the testing node's own copy of the same file. The first file that does not stops the test and is named in the result.

What a failure usually means

  • Connection refused or timed out — the web server on the target is down, or a filter on the path blocks TCP port 80.
  • HTTP 404 on every file — the target runs an older build without this site. Push the current build to it from the hub dashboard.
  • Content changed — the file arrived but is not what was sent. Transparent proxies, content filters and some firewalls insert or rewrite HTML. A shorter byte count than the original points to a transfer that was cut off.
  • Only report.html fails — small files pass and the large one does not. Look at MTU and MSS on the path; the M column tests path MTU directly.

What it does not do

It does not test HTTPS. The node web server is BusyBox httpd, which serves plain HTTP only. It does not load images or follow links automatically; the order above is fixed so that every run makes the same requests.

Timing

The reported latency is the total time of all five requests. Each request has a five-second connect timeout and a ten-second overall limit, and the test stops at the first failure, so a black-holed target costs about as much as a single request did before.
