End-to-end probe site

This small site is served by every Pervium node. Other nodes fetch it the way a browser would — the page, its stylesheet, its script, then two more pages — and compare every byte with their own copy. A page that arrives changed or cut short means something on the path is rewriting or truncating web traffic.

The content is fixed and identical on every node. Do not edit these files on one node only: every peer would then report its HTTP test as failed against it.

Why fixed content

A status code only proves that something answered. Comparing the body proves that what the server sent is what the client got: no injected banner, no rewritten links, no transfer that died half way through a large page.

Why several files

Real browsing is several requests in a row over the same path, of different sizes and content types. Inspection engines treat HTML, CSS and JavaScript differently, and a large page crosses many packets where a small one fits in one.

What fails the test

Any file that does not answer 200, or whose SHA-256 differs from the local copy. The test output names the first file that failed and how many bytes arrived.

Client-side check

The script has not run.
